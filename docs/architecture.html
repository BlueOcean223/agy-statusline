数据从哪来，画在哪里

agy-statusline 的三种实现方式对比，以及最终采用的结构。基于 Antigravity 2.33.0（macOS）实测。

先说结论

你提的方向（插件注册、hook 拿数据、CDP 只画）是对的，但要改一处：hook 拿不到用量数据。hook 的 stdin 只有 conversationId、modelName、transcriptPath、invocationNum 这类元数据，没有 token、上下文、缓存、额度。真正的数据源是 language_server 的只读 API，而且 Antigravity 本来就把它的地址和 csrf token 以环境变量交给了插件的 sidecar 进程（ANTIGRAVITY_LS_ADDRESS、ANTIGRAVITY_CSRF_TOKEN）。

所以最终分工是：sidecar 取数并计算，hook 只负责报告“某个对话发生了什么事件”，CDP 只负责画。

三种做法

A · agy-zh-pack 的做法

页面内旁听

外部 Node 进程用 CDP 注入脚本；脚本包一层 window.fetch，旁听应用和后台之间的 grpc-web 流，再借用截获的请求头自己查额度等接口。

必须在应用脚本之前装好 fetch 包装，晚到要刷新窗口

依赖前端的流格式和字段名，前端改了就坏

要另装常驻进程和开机自启

B · 原来的 agy-statusline

侧栏面板 + 读 transcript

sidecar 提供右侧面板，hook 记毫秒时间，数据从 transcript.jsonl 解析。

不用调试端口，全走官方插件机制

只能放在侧栏，不在输入框上方

transcript 没有首字时间、上下文上限、实际模型名、真实额度，只能估算

C · 现在采用

sidecar 取数 + CDP 只画

sidecar 用官方给的地址和 token 调 language_server 只读 API；hook 发一个 UDP 包让它立刻刷新；CDP 注入一个纯渲染脚本，数据由 sidecar 推进去。

数据和参考项目一样全（含首字、实际模型、真实 5h/周额度）

不改应用的任何请求，不依赖 fetch 包装时机

Antigravity 自己负责拉起和重启 sidecar

画在输入框上方仍需带 --remote-debugging-port 启动

hook 在这里的位置

  • hook 同步执行、会阻塞 agent 循环，所以只做一件事：向 plugin_data/live.port 里的端口发一个 UDP 包，不等回应。实测单次 ≤10ms。
  • 没有 hook 也能工作，只是数据要等下一次轮询（运行中最多 2 秒）。

还要你决定或注意的

  • 重启后的对话：Antigravity 重启后 language_server 只列出已加载的对话。sidecar 每 30 秒扫一遍 brain/，今天动过的对话主动查一次（查询会让后台加载它）；面板的“自动跟随”和最近对话列表按 annotations/ 的最后查看时间排。
  • 为什么轮询而不用 binding：Runtime.addBinding 绑定在添加它的 CDP 会话上。sidecar 升级或被重启后，旧进程注入的页面还在调用已失效的 binding，新进程收不到。
  • 调试端口：2.33.0 起只有带 --remote-debugging-port 启动才有。开了以后本机任何进程都能通过它控制 Antigravity 窗口。
  • 单价是公开 API 标准价折算，不是订阅实际扣费。
  • 中文界面：翻译脚本和词典来自 agy-zh-pack（MIT，i18n/），编进二进制。打开时 addScriptToEvaluateOnNewDocument 注册并立即执行一次；关闭时撤掉注册并停止翻译，已翻译的文字要刷新窗口才恢复。
  • 重启按钮：sidecar 起一个独立进程组的 shell 脚本，osascript 让 Antigravity 退出，等进程消失（最多 60 秒）后 open -a Antigravity --args --remote-debugging-port=0。sidecar 会随 Antigravity 退出，所以脚本不能是它的普通子进程。

页面结构依赖：输入框 [data-testid="agent-input-box"]，对话 ID 取自 [data-testid="conversation-view"][data-cascade-id]（子代理标签页取 subagent-tab-conversation）。这两个选择器沿用 agy-zh-pack 在 Windows 版上验证过的，macOS 版尚未在真实窗口里验证。
